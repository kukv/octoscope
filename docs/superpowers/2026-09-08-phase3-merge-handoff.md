# Phase 3（merge）の受け渡し — 実端末での確認

**この環境には TTY が無く、`kukv/octoscope` に開いている PR も無かったので、実端末での確認は
代行できない。** ここまでの確認はすべて golden recording を通してのもので、実際の画面で
このポップアップを見た人はまだいない。**これがこの文書の一番大事な用件である。**

## 先に

**マージは戻せない。** 試す前に、捨ててよいプルリクエストを 1 つ作ること。本物の PR を
対象に `enter` を押す前に、必ず自分が壊してよいものであるかを確かめる。

## 用意するもの

- 自分が所有する、捨ててよいプルリクエスト（実マージを試す用）
- できれば、マージ方式が複数許可されているリポジトリ（`kukv/octoscope` は 3 方式とも許可、
  `deleteBranchOnMerge: true` — 2026-09-08 実測）

## 手順

1. 起動して PR を開き、詳細ビューで `m` を押し、マージのポップアップが出ることを確かめる
2. `j` / `k` でマージ方式にカーソルが動くことを確かめる。`kukv/octoscope` では
   squash / merge commit / rebase の 3 つが出るはずである（リポジトリの設定と合っているか
   確かめる）
3. `enter` で実際にマージし、次を確かめる:
   - 成功したら詳細ビューが閉じる
   - Work 板を取り直すと、マージされた PR のカードが消えている
   - `kukv/octoscope` は branch を消す設定なので、GitHub 側でブランチが削除されている
4. `r` で取り直しが効くことを確かめる。特に、`⚠` の理由（レビュー待ち、コンフリクトなど)が
   PR の実状と合っているか。`UNKNOWN` のまま止まっている理由が `r` で解けて
   `CONFLICTING` 等の実値に変わるかも見る
5. マージできない PR（レビュー待ち、コンフリクトなど）を開き、`enter` が塞がれ、
   `⚠` の理由が表示だけされることを確かめる

## auto-merge — `kukv/octoscope` では確かめられない

**`kukv/octoscope` は `autoMergeAllowed: false`**（2026-09-08 実測。Phase 3 の設計時にも
同じ値を確認済み）。そのため、次の 2 つはこのリポジトリでは試せない:

- space で auto-merge を選び、`enter` で予約する
- 既に auto-merge が予約された PR を開き、`enter` が予約解除になる

確かめるには、次のどちらかが要る:

- `kukv/octoscope` のリポジトリ設定で "Allow auto-merge" を入れる
- それが最初から入っている別のリポジトリを `--repo` で指す

auto-merge が使えるリポジトリで確かめてほしいのは:

- space でチェックボックスが切り替わり、`enter` で予約されること
- 予約済みの PR を開くと、方式の選択ではなく「予約を解除する」の 1 行だけになり、
  `enter` でその解除が届くこと

## 幅の確認

```bash
go run ./cmd/octoscope --lang ja
```

詳細ビューを開き、80 桁の端末で `m` を押し、次を確かめる:

- ポップアップ自体が壊れていない（枠、方式の一覧、キーバーの桁がずれない）
- 英語（`--lang ja` を外した状態）でも同様

**分かっていて直さないことにした点**: 80 桁・日本語では、詳細ビューのキーバーが
`x:クローズ` と `r:更新` を落として `m:マージ` の場所を空ける。キー自体は効くので、
落ちるのはヒントの表示だけである。実端末でこの通りになっているか、ヒントが欠けた状態で
崩れていないかを見る。

## この段階で分かっていること

- **仕様書 §4.4.4 は Task 7 で訂正した。** `mergePullRequest` にブランチ削除の入力は無く、
  `MergeStateStatus` に `DRAFT` は無い。ブランチ削除はリポジトリの設定を読むだけの表示で、
  カーソルは乗らない。ドラフトは別の仕組みで弾く
- **確認画面は無い。** ポップアップで `enter` を押した時点でそのまま送信される
- **失敗は GitHub のメッセージをそのまま出す。** このビュー独自の言い換えは無い

## 報告してほしいこと

- 方式の一覧がリポジトリの設定（許可されている方式、ブランチ削除の有無）と合っているか
- `⚠` の理由が PR の実状と合っているか、`UNKNOWN` が `r` で実値に解けるか
- マージ後、詳細ビューが閉じて Work 板からカードが消えるか
- ポップアップが 80 桁で壊れていないか（英語・`--lang ja` の両方）
- auto-merge を別リポジトリで試せた場合、予約と解除の両方が届くか
