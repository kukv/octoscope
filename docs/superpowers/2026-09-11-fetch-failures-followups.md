# 取得の失敗から立ち直るスライスの積み残し

`docs/superpowers/specs/2026-09-11-fetch-failures-design.md` の実装（Task 0〜6）で
見つかったが、このスライスでは直さなかったもの。**直さないと決めた理由も書く。**

## 実端末での確認の依頼

`.claude/rules/tui.md` および過去のスライス（`2026-09-09-phase4-repos-sidebar-followups.md`
の「実端末での確認の依頼」）と同じく、TTY の無い環境では代行できないため、
利用者に見てほしいものを列挙する。

- 通知が出ている Work 板（1 列だけ失敗した状態と、全列成功した状態の両方）
- `--lang ja` の 80 桁（通知の行とキーバーが両方収まること）
- `r` で引き直し、成功したら通知が消えること
- `gh` を PATH から外したとき、あるいは未認証のときに全画面のエラー画面へ行くこと

## オーバーレイ（詳細・diff・checks）は全画面のままであること

設計 §4 は「`ErrGhNotFound` / `ErrUnauthenticated` 以外はすべてタブの 1 行に出す」と
書いているが、この計画ではオーバーレイ（詳細・diff・checks）をその範囲から外し、
全画面のエラー遷移のままにした。

**理由:** オーバーレイは `esc` で常に一つ手前の画面に戻れる。取得の失敗をオーバーレイの
1 行に出す仕組みを新たに作らなくても、`esc` を押せば板の一覧という「立ち直れる場所」に
戻れており、利用者は既に立ち直れる。オーバーレイ専用の通知行を持たせる価値は、
Work 板の通知行ほど高くない。

## 見つかったが直さなかったこと（理由つき、4 件）

### 1. ja の 80 桁で、Work 板の読み込み中のスピナー行が句点で切れる

`⣾  読み込み中.…` のように、句点 1 つ + 省略記号で切れて読みにくい。桁は揃っており
実害は無い。golden は `internal/tui/work/testdata/app_tabs_work_ja_80.golden`。

**直さなかった理由:** レイアウトは仕様どおり崩れておらず、文言の詰め方だけの問題。
i18n の文言テンプレートを触る変更になるので、このスライスの範囲（取得の失敗からの
回復）を超える。

### 2. `o`（ブラウザで開く）の失敗通知を、利用者が自分で消す手段が無い

この通知は `r` での再取得でも、レビュー送信などの `Refresh` でも消えないようにした。
理由は、取得が成功しただけで「手で開くべき URL」が画面から消えてしまうのを防ぐため。
結果として、**この 1 行は行（カード）を移るまで残り続け、利用者が明示的に消す手段が
無い。**

**直さなかった理由:** 意図した挙動（成功で消してはいけない通知がある）であり、
バグではない。ただし消す手段を持たせるかどうか（例えば別のキーで明示的に消す）は
設計判断が要るので、次のスライスで決める。

### 3. `internal/tui/repo/repo_test.go:352` が文言だけで足りるところで `cmd()` を実行している

`t.Fatalf("… %T", cmd())` が、setup が崩れたことを報告するためだけに `cmd` を
実際に実行している。`fakeSource` を使っているので実害は無いが、文言だけで足りる。

**直さなかった理由:** このスライスが持ち込んだ行ではなく、実害も無い nit。
直すこと自体に技術的な判断は要らないが、このスライスの変更範囲に含まれない
既存コードなので、`.claude/CLAUDE.md` の「触れるべき箇所だけに触れる」に従って
見送った。

### 4. 即時再試行の成功率が、実測できていない

設計 §6 に「実装時に即時再試行の成功率を実測する」という宿題があったが、
実測した 30 回すべてが成功し、502 を 1 回も引かなかったため、再試行そのものが
一度も発生しなかった。上限 30 回（アカウントと GitHub の GraphQL レート予算を
使うための裁定）を使い切っており、502 を待って回し続けることはしていない。

**直さなかった理由:** 数字が無い以上、遅延の有無を決める根拠が無い。根拠の無い
数字（外挿・推定）を書くより、「測れなかった」と明記して現状の形（遅延なし・
読み取りを 1 回だけ引き直す）を変えないことにした。次に実際に 502 を引いたときに、
即時再試行が成功したかどうかをその場で記録し、設計 §6 を書き直すこと。
