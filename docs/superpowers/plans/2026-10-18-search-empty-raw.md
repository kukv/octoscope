# Search: 生クエリを空で確定したらフィルタに戻る、を仕様にする（#180）

## 問題

`e` で生クエリを全部消して確定すると `raw` が空になり、フィルタから組み立てた検索に戻る
（`internal/app/presentation/tui/search/search.go` の `handleRawKey` と `query`）。型が string なので
「未設定」と「空」を区別できず、この挙動は決めたものではなく結果としてそうなっている。

## 方針

**空で確定したら、生クエリをやめてフィルタに戻る。** 空のクエリは GitHub の検索として成り立たないので、
区別して持つ意味が無い。区別が要らないと決めたので、`*string` は入れない（Issue の受け入れ条件の
「型で表す」は採らない）。

空白だけの入力も空とみなす。`handleRawKey` の `enter` で、`strings.TrimSpace` が空なら `raw` を空にする。
空でない入力は、前後の空白も含めて入力のまま持つ（今と同じ）。

`raw` のコメントに「空は未設定と同じ意味で、フィルタに戻る」ことを書く。

## タスク

1. テスト（赤）: フィルタを 1 つ設定し、生クエリを入力して確定してから、`e` で開いて全部消して確定する。
   次の検索がフィルタから組み立てたクエリで走り、フィルタペインが薄く描かれない。空白だけを入れて
   確定しても同じ
2. `handleRawKey` を直して緑にする（空の場合は今の挙動のままなので、テストは空白のケースで赤になる）
3. `make check`
4. 実際に起動して、Search タブで同じ操作をする
