# detail: ラベル・担当者の適用に失敗したら再取得する（#150）

## 問題

api バックエンドの `editLabels` は POST で追加してからラベルごとに DELETE する。
追加の後に削除が失敗すると GitHub には追加だけが残るが、`pickFailed` は
エラーを出してピッカーを開いたままにするだけで再取得しない。画面は編集前のまま。

## 決めたこと（利用者と合意）

適用に失敗したら**ピッカーを閉じて詳細を取り直し**、エラーには翻訳した前置き
「一部だけ適用された可能性があります」を付けて原文を続ける（`.claude/rules/errors.md`）。
再試行は `l` / `a` で開き直す——最新の状態から差分を作り直すので、古い差分を
もう一度送るより正しい。

これまでの「開いたまま」（`TestPickerApplyErrorKeepsPicker`）は、部分適用を
考えていなかった前提の上にある。書き換える。

## 実装

- `pickFailed` の適用失敗の分岐（`phaseWorking`）: `modeView` / `phaseLoading` にして
  取り直す。候補の取得失敗の分岐は今のまま
- 取り直しの答え `itemMsg` に、直前に失敗した編集のエラーを載せる（`editErr`）。
  `itemArrived` は `errText` を消すので、載せないとエラーが取得と同時に消える
- i18n: `detail.edit_partial`（en / ja）
- 取り直し自体が失敗したら、その失敗が出る（`fetchFailed` の既存の経路）
