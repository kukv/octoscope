# diff: r の取り直しの途中で別の操作をしたら、その取り直しをキャンセルする（#232）

## 問題

#227 で、書き込み（行コメント・破棄・`v` でレビューを送る）のたびの取り直しをやめた。全体を取り直すのは
diff を開いたときと `r` だけになったが、`r` の返事が届く前に書き込むと、あとから届いた `r` の返事
（書き込む前の状態）で画面が上書きされる。破棄したコメントが「未送信」でまた出る、送ったコメントが消える。

書き込みの最中は、コメント入力・破棄の確認・送信のポップアップが開いていて `r` は効かない
（`handleKey` は `modeView` のときだけ `r` を見る）。起きる順番は「`r` → 返事の前に書き込む」だけ。

## 方針

**別の操作を始めたら、それより前に始めた取り直しをキャンセルする。** 返事はもう届きかけていることがあるので、
キャンセルは「その返事が届いても使わない」で表す。

- `Model.reviewGen` を持つ。`reviewMsg` / `reviewErrMsg` は、問い合わせを始めたときの `reviewGen` を運ぶ
- コメント入力を開いたとき（`startComposing`）、破棄の確認を開いたとき（`startDiscard`）、送信のポップアップを
  開いたとき（`openSubmit`）に `reviewGen` を進める。どれも、その操作を始められると決まったあと
- `reviewArrived` / `reviewFailed` は、運んできた番号が今の `reviewGen` と違えば何もしない

開いたときに進めるのは、利用者の言う「別の操作をしたらキャンセル」そのままで、書き込みの途中に届く返事も
捨てられるため。書き込みが終わってから進めると、コメントを送っている最中に届いた返事に GitHub がもう
受け付けたコメントが入っていた場合、送信の結果を足したときに同じコメントが 2 つ並ぶ。

入力を開いて `esc` でやめた場合も、キャンセルした取り直しの返事は使わない。ほかの人のコメントを見たければ
もう一度 `r` を押す。

却下: 返事が届くまで 3 つの操作を受け付けない。レビューの情報は取得に数秒かかることがあり、そのあいだ
操作できなくなる。

却下: 問い合わせそのもの（gh のプロセス・HTTP）を `context` で止める。止めても届きかけの返事は捨てる
必要があり、`Model` が値で渡るので cancel 関数の持ち回りが要る。通信を 1 本減らすだけの利得に見合わない。

範囲外: `r` を続けて 2 回押したときの返事の前後。どちらも書き込みの前の最新に近く、画面を壊さない。

## タスク

1. テスト（赤）: `r` を押し、その問い合わせの番号を控える。3 つの操作のそれぞれを開いてから、控えた番号で
   古い返事（目印の本文を含む）を渡す。`View()` に目印が出ない。番号が今のものなら今までどおり反映される
2. 実装して緑にする。既存のテストで、操作を開いたあとに `reviewMsg` を渡しているもの
   （入力中に取り直しが届く場合のテストなど）は、今の番号の返事として渡すように直す
3. 3 か所それぞれで番号を進めるのをやめ、1 のテストが落ちることを確かめる
4. `make check`
5. 実際に起動して確かめる。回線が遅いとき以外は `r` の返事がすぐ届くので、gh の前に置いた shim で
   レビューの問い合わせだけを遅らせる
