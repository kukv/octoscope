# 設定ファイルへの保存を直列にする（#187）

## 問題（調べて分かったこと）

Issue は「read-modify-write に排他が無いので更新が失われうる」と書くが、失われ方は 2 つある。

1. **別の設定どうし。** `SaveRepositories` と `SaveQueries` が並行すると、片方が読んだ後に
   もう片方が書き、先の方が古い内容で上書きする。これは read-modify-write の競合
2. **同じ設定の連続保存**（Issue の例「picker で `x` を 2 回」）。各保存は UI の最新の一覧を
   丸ごと書くので、read-modify-write では失われない。失われるのは **2 本の `tea.Cmd` の
   goroutine の実行順が逆転したとき**——古い一覧が後から書かれる。mutex では順序は保証できない

## 方針（利用者と合意）

- **Store:** `sync.Mutex` で `load` から `save` までを 1 本ずつにする（1 を塞ぐ）
- **repo / search ビュー:** 保存は同時に 1 本。保存中にもう一度保存したくなったら
  `saveAgain` を立てて待ち、今の保存が終わったら（成功でも失敗でも）その時点の最新を
  もう一度書く（2 を塞ぐ）。成功は今まで `nil` を返していたが、終わりを知るために
  `savedMsg` を返す
